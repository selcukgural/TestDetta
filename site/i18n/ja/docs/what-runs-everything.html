すべてが実行される変更

ほとんどの変更では、選択されるテストクラスはわずかです。しかし安全に絞り込めない変更もあり、その場合 {{name}} はテストプロジェクト全体、またはフォルダー配下のすべてのプロジェクトを実行します。このページではそうした変更をすべて挙げているので、選択が広くなっても驚くことはありません。

ビルド全体に関わるファイル

これらのファイルは、その配下にあるすべてのプロジェクトのビルド方法を変えます。いずれかを変更すると、そのフォルダーとその配下にあるすべてのテストプロジェクトが実行されます。

ファイル実行されるもの
Directory.Build.props、Directory.Build.targets、Directory.Build.rsp配下のすべてのテストプロジェクト
Directory.Solution.props、Directory.Solution.targets配下のすべてのテストプロジェクト
global.json、NuGet.config、.editorconfig配下のすべてのテストプロジェクト
Directory.Packages.props（PackageVersion 項目だけが変更された場合）変更されたパッケージを参照するテストプロジェクトと、それに依存するテストプロジェクトだけ
カバレッジマップがない、ポータブル PDB なしでビルドされる、または複数のフレームワークのうち 1 つだけを -f で記録したテストプロジェクトに対する、変更されたソースジェネレーター生成されるコードはビルドから比較しますが、この場合は比較する対象がないため。それ以外の場合は、変更された生成コードだけが対象になります。
ReferenceOutputAssembly="false" で参照され、変更されたプロジェクト（参照する側のビルドがその出力をコンパイルするコードに変える場合、またはテストプロジェクトのマップがどのテストがそれを起動・読み込みしたかを記録していない場合）それ以外の場合は、マップの記録時にそれをプロセスとして起動した、または読み込んだテストクラスだけが実行され、ビルド順序のためだけの参照は何も実行しません。

テストプロジェクト全体が実行される変更

変更絞り込めない理由
プロジェクトファイル、またはそれがインポートする .props や .targets ファイルプロジェクト内のあらゆるもののビルド方法を変えうるため。
プロジェクト内の C# 以外のファイル（appsettings.json、.resx、テストデータファイルなど）誰がそれを読み込むかを示すカバレッジマップがないため。
global using またはアセンブリ属性すべてのファイルに適用されるため。
どの宣言にも属さないコードでの C# の変更（プリプロセッサ条件の下にあるコードなど）たどるべきメンバーがないため。
どこからも名前で参照されていないものの、フレームワークがリフレクションで検出しうる型の変更（コントローラー、メッセージハンドラー、EF の構成など）名前からもカバレッジからも、誰がそれを見つけるかわからないため。
F# または Visual Basic のプロジェクトでの変更そのコードは分析されないため。
アナライザーやソースジェネレーターとして使われるプロジェクト影響が呼び出しではなくコンパイルに及ぶため。

これらはいずれも、影響を受けたプロジェクトに依存するすべてのテストプロジェクトも実行します。

カバレッジマップの状況

  • 古いマップと、その間のビルドの変更。マップがマージベースより数コミット古く、その間にビルドファイルや構成ファイルが変更されている場合、影響を受けるテストプロジェクトは丸ごと実行されます。--drift-fallback name を指定すると、代わりに名前で判断します。ドリフトブリッジを参照してください。
  • すべてのクラスが選択された場合。すべてのクラスが選択されたプロジェクトは、フィルターなしで実行されます。
  • 何にも一致しないフィルター。そのプロジェクトはフィルターなしで再実行され、{{name}} はこれを自身のバグとして扱います。

マップがまったくない場合でも、すべてが実行されるわけではありません。選択は名前によるトレースにフォールバックします。カバレッジよりは広くなりますが、それでも絞り込まれた選択です。

どのプロジェクトにも属さないファイル

README.md、.github/ 配下のファイル、リポジトリのルートにあるテストデータなど、すべてのプロジェクトフォルダーの外にある変更ファイルは、どのプロジェクトにも属しません。カバレッジマップの記録中にテストがパスを指定してそのファイルを読んだ場合、そのファイルの変更、またはテストが一覧を取得したフォルダーへの新しいファイルの追加は、それを読んだテストクラスを実行します。テストの外、フィクスチャのセットアップ中、またはテスト間で共有されるものの初期化中に読まれた場合は、テストプロジェクト全体が実行されます。記録されたどのテストも読まなかったファイルは何も選択しません。出力では、これらのファイルを記録されたテストが読んだものと、どのテストも読まなかったものに分けて数えます。

読み込みは、リポジトリ自身のプロジェクトのコードで記録されます。サードパーティのライブラリ内部（たとえば .verified ファイルを読むスナップショットライブラリ）は対象外で、読み込みを記録するバージョンで記録したカバレッジマップにだけ含まれます。そのように読まれるファイルはテストプロジェクト内に置くか、<None Include="..\..\testdata\**" CopyToOutputDirectory="PreserveNewest" /> のようにプロジェクトの項目として指定してください。そうすれば、ファイルがどこにあってもそのプロジェクトに属し、変更や削除でプロジェクトが実行されます。

例外が 1 つあります。どのプロジェクトにも属さないソースファイルやビルドファイル（.cs、.fs、.vb、.props、.targets、.projitems）は、インポートを完全には解決できなかったすべてのプロジェクトのビルド入力とみなされ、それらのプロジェクトが実行されます。
