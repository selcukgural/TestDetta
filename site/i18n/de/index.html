Zwei Schritte in GitHub Actions

Ihr Standard-Branch zeichnet einmal auf. Jeder Pull Request führt danach nur aus, was er betrifft.

  1. bei Push auf main

    Coverage-Map aufzeichnen

    Jeder Test läuft einmal mit Coverage. Die Map wird unter ihrem Commit im Actions-Cache gespeichert.

  2. Actions-Cache testdetta-coverage-<sha>
  3. bei Pull Request

    Ausführen, was die Änderung betrifft

    Die neueste Map an oder vor der Merge-Base wird wiederhergestellt, nur die betroffenen Testklassen laufen, und die Job Summary sagt, warum jede davon lief.
