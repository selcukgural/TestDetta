Lizenz

Öffentliche Repositorys nutzen {{name}} kostenlos. Private Repositorys übergeben der CI einen Lizenzstring. Ein Lizenzproblem lässt nie einen Build fehlschlagen: Ohne gültige Lizenz laufen alle Tests, wie vor {{name}}.

Öffentliche Repositorys

Ein öffentliches Repository benötigt keine Lizenz, aber {{name}} weiß nur dort, dass ein Repository öffentlich ist, wo die CI es angibt:

  • GitHub Actions: aus dem Event-Payload (repository.private);
  • GitLab CI: aus CI_PROJECT_VISIBILITY.

Unter Jenkins, Azure DevOps, Bitbucket, anderen CI-Systemen und auf Entwicklerrechnern gilt jedes Repository als privat.

Die Lizenz übergeben

{{name}} sucht die Lizenz in dieser Reihenfolge:

  1. TESTDETTA_LICENSE: der Lizenzstring, aus einer maskierten oder geheimen Variable;
  2. TESTDETTA_LICENSE_FILE: der Pfad einer Datei, die ihn enthält;
  3. ~/.testdetta/license: geschrieben von td license install und von der automatischen Aktualisierung;
  4. .testdetta/license im Repository.

Eine geheime Variable ist der empfohlene Weg. In GitHub Actions übergeben Sie sie über die Eingabe license der Action:

- uses: {{actionRef}}
  with:
    mode: test
    license: ${{ secrets.TESTDETTA_LICENSE }}

Nur td affected, td test (nicht td test --shadow) und td license status lesen die Lizenz. td record, td test --shadow und td audit führen ohnehin alle Tests aus und benötigen keine.

Die Lizenz prüfen

td license status zeigt, was die gefundene Lizenz abdeckt: ihre Gültigkeit, die abgedeckten Repositorys und die Anzahl aktiver Committer, ohne personenbezogene Daten. Derselbe Status erscheint im Log, in der Job Summary und in der JSON-Ausgabe, wann immer er relevant ist: gültig, läuft bald ab, Seats überschritten, noch nicht gültig, abgelaufen, falscher Scope, ungültig oder fehlend.

td license status

Rechner ohne CI-Secrets

Wo keine geheime Variable die Lizenz aufnehmen kann, speichern Sie sie einmal pro Rechner:

td license install <license|file>

Sie wird zuerst geprüft und dann nach ~/.testdetta/license geschrieben.

Automatische Erneuerung

Eine Lizenz enthält die Adresse, von der sie erneuert wird. Höchstens einmal am Tag pro Rechner ruft {{name}} die aktuelle Version ab und legt sie in ~/.testdetta/license ab, sodass Verlängerungen und zusätzliche Seats ankommen, ohne dass Sie Ihre Secrets anfassen müssen. Die Anfrage sendet die Lizenz in einem Header und nichts aus Ihrem Repository. Sie läuft parallel zur Analyse mit einem Timeout von 6 Sekunden, und jeder Fehler wird ignoriert. Ein Fehler, der vorübergehen kann (keine Antwort, ein Timeout, ein Serverfehler), wird nach einer Stunde erneut versucht. Ein blockiertes Netzwerk kostet so höchstens einige Sekunden pro Stunde, meist verdeckt durch die Analyse; setzen Sie TESTDETTA_LICENSE_REFRESH=off, wo der Dienst nicht erreichbar ist. HTTPS_PROXY wird berücksichtigt. Der Zeitpunkt des letzten Versuchs wird in ~/.testdetta/license-refresh festgehalten, sodass die Erneuerung auf CI-Runnern, die mit einem leeren Home-Verzeichnis starten, einmal pro Job läuft.

Die Lizenz eines Abonnements reicht höchstens 40 Tage voraus und wird nur auf diesem Weg erneuert: Solange das Abonnement läuft, liefert jede Aktualisierung eine Lizenz, die wieder 40 Tage vorausreicht, sodass eine CI, die aktualisiert, nichts davon merkt. Eine Kopie, die den Lizenzdienst nicht erreicht, läuft nach höchstens 40 Tagen ab, mit Warnungen in den letzten 14. Für ein Netzwerk, das den Lizenzdienst nicht erreichen kann, wählen Sie den Jahresplan: Seine Lizenzdatei gilt für die ganze Laufzeit, und Sie setzen TESTDETTA_LICENSE_REFRESH=off.

Welche Repositorys eine Lizenz abdeckt

Eine Lizenz benennt die Repositorys, die sie abdeckt, etwa github.com/acme/* (alle Repositorys von acme) oder github.com/acme/app (eines). Was Sie beim Kauf oder im Testformular angeben, wird in diese Form gebracht: Eine URL oder ein SSH-Remote wird zu Host und Pfad, und eine Organisation allein (github.com/acme) deckt alle ihre Repositorys ab. {{name}} gleicht sie mit dem Remote origin des Repositorys ab. In die Remote-URL eingebettete Anmeldedaten, wie sie bei Jenkins üblich sind, werden vor dem Abgleich entfernt und nie geloggt.

Wenn der Remote nicht das Repository benennt, das die Lizenz abdeckt, zum Beispiel bei einem lokalen Mirror, setzen Sie TESTDETTA_LICENSE_SCOPE:

TESTDETTA_LICENSE_SCOPE=git.acme.corp/scm/pay/app

Aktive Committer

{{name}} wird pro aktivem Committer und Monat abgerechnet: ein eindeutiger Commit-Autor mit mindestens einem in den letzten 30 Tagen verfassten Commit unter den Commits, die vom analysierten Commit aus erreichbar sind. Autoren werden lokal gezählt, anhand der über .mailmap zusammengeführten E-Mail-Adresse, und keine E-Mail-Adresse verlässt Ihre Rechner. Bots wie Dependabot, Renovate und github-actions werden nicht gezählt; eigene Muster fügen Sie in .testdetta/license.json hinzu:

{ "bots": ["ci-service-account"] }

Die Seats einer Lizenz decken die aktiven Committer aller von ihr abgedeckten Repositorys zusammen ab. Da keine Identität Ihre Rechner verlässt, kann {{name}} nur das Repository zählen, in dem es läuft; Anzahl und Warnungen beziehen sich daher immer auf ein einzelnes Repository. Kaufen Sie Seats für alle Personen in allen diesen Repositorys.

Bis zu 20 % über den Seats der Lizenz (mindestens eine Person) sind in Ordnung. Darüber hinaus wählt {{name}} 30 Tage lang weiter aus und warnt in jeder Zusammenfassung, sodass Zeit bleibt, Seats hinzuzufügen; erst wenn die Anzahl danach immer noch darüber liegt, laufen alle Tests, wie ohne Lizenz. Siehe Preise.

Nie ein roter Build: Eine abgelaufene, fehlende oder nicht passende Lizenz führt dazu, dass {{name}} alle Tests ausführt und den Grund nennt. Der Job schlägt dadurch nicht fehl.
