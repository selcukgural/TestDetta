Die Änderung

Eine Umbenennung im Paket für die deklarative Konfiguration: Das Flag, das angibt, ob OTEL_CONFIG_FILE überschrieben wird, bekommt einen Namen, der genau das sagt. Es ändert kein Verhalten, ist aber eine Codeänderung, daher würde eine normale Pipeline jedes Testprojekt im Repository bauen und ausführen.

{{name}} verfolgt die Änderung von der Datei bis zu den Tests, die sie bemerken können. Die geänderte Methode ist privat; nur UseDeclarativeConfiguration ruft sie auf. Der eine übersehene Fall ist der von NLog: Eine Testklasse las eine Einstellung, die eine frühere Klasse hinterlassen hatte, und schlug in einem sauberen Wiederholungslauf erneut fehl; {{name}} erkennt solchen Zustand noch nicht (Einschränkungen). Ein zweiter übersehener Fall, den die Runde meldete, in Meziantou.Analyzer, war ein Testhost, der einmal unter Last abstürzte und beim erneuten Lauf bestand; nach der endgültigen Fassung der Regel (ein Absturz außerhalb der Auswahl ist nur dann ein übersehener Fall, wenn er wiederkehrt) ist er keiner. {{corpusInconclusive}} Änderungen waren nicht eindeutig. Jeder frühere echte übersehene Fall erhielt einen Test, der ohne die Korrektur fehlschlägt, und sein Repository lief erneut, bis es sauber war.
