The change

A one-line refactor in the Rule widget. It changes no behaviour, but it is a code change, so a normal pipeline would run all 787 tests in 141 classes on every target framework.

How the decision was made

{{name}} follows the change from the file to the tests that can observe it. The coverage map, recorded on main, knows which test classes ran the changed method; the other 127 ran none of it and name none of it.

Across 40 repositories

One change is one data point. To know how {{name}} behaves on code it has never seen, we run it on 40 open-source .NET libraries and check every selection against the tests that really fail.

  1. RecordA coverage map at the head of the default branch.
  2. Change one memberUp to 100 sampled methods, properties and constructors, one at a time.
  3. Break it and run everythingThe member throws, and the whole suite runs to see which classes fail.
  4. Check the selectionEvery failing class must be one {{name}} selected. A miss is confirmed by running the class alone.

Where it gains most

Layered code, where each test reaches a small part of the system, gains most: OpenTelemetry .NET ran 6% of its test classes per change, Polly 7%, Roslynator 8%. Libraries where nearly every test runs the same core gain little: Scriban 100%, Markdig 98%, Mapperly 89%. There, a change to the core really does reach most tests, and {{name}} runs them.
