The change

A rename in the declarative configuration package: the flag that says whether OTEL_CONFIG_FILE is overridden gets a name that says so. It changes no behaviour, but it is a code change, so a normal pipeline would build and run every test project in the repository.

How the decision was made

{{name}} follows the change from the file to the tests that can observe it. The changed method is private; only UseDeclarativeConfiguration calls it. The coverage map, recorded on main, knows which test classes ran it: 8 classes in one test project. The other 266 ran none of it and name none of it.

Latest round of the evaluation, 2026-10-07 to 2026-10-08, judged strictly: a test run that crashes or hangs outside the selection counts as a miss unless the same run without the change shows it is not the change's. Of 48 repositories, {{corpusRepositories}} finished; Orleans, Akka.NET, Lucene.NET, ABP and MSBuild were not run in this round. The one miss is NLog's: a test class read a setting an earlier class had left behind, and it failed again in a clean rerun; {{name}} does not see such state yet (Limitations). A second miss the round reported, in Meziantou.Analyzer, was a test host that died once under load and passed when run again; under the rule's final wording (a crash outside the selection is a miss only when it comes back) it is not one. {{corpusInconclusive}} changes were inconclusive. Every earlier real miss got a test that fails without the fix, and its repository ran again until clean.

Where it gains most

Layered code, where each test reaches a small part of the system, gains most: Polly ran 3% of its test classes per change, Spectre.Console 6%, OpenTelemetry .NET 8%. Libraries where nearly every test runs the same core gain little: Mapperly 97%, EF Core 89%, AutoMapper 85%. There, a change to the core really does reach most tests, and {{name}} runs them. LibGit2Sharp ran everything (100%): a reference that depends on the target framework keeps {{name}} conservative there.
