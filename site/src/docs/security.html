Security and data

{{name}} runs in your CI and on your machines. Your source code and test results never leave them; coverage maps leave them only for your CI's cache storage. This page lists everything it stores and every network call it makes.

What stays in your CI

  • The analysis of your diff and source code.
  • Coverage maps: which test class ran which method, and how long each class took. They name your types, methods and test classes, so treat them like build artifacts.
  • Test runs and their results.
  • The count of active committers. Author emails are read from git history to count them, on your machine; no names or emails are sent anywhere.
  • td record instruments assemblies in the test project's build output while it runs: your repository's, and third-party ones there that read files. It backs up the originals in a temporary testdetta-record-* folder first and puts them back at the end, also when the recording fails. It also copies its runtime into the build output and lists it in the test project's deps.json, both undone at the end, and the test process sets a startup hook (DOTNET_STARTUP_HOOKS) for the .NET processes the tests start, so that each reports which test started it.
  • td audit rewrites assemblies only in its own copy of the working tree; your sources and build output are only read, and the copy is deleted at the end.

On GitHub Actions, maps are stored in your repository's Actions cache. .testdetta/coverage/ and .testdetta/cache/ are generated; keep them out of version control.

The one network call

With a trial or subscription license, {{name}} asks the license service for a renewed license at most once a day per machine (once per job on CI runners that start with an empty home directory), so that renewals reach CI without anyone updating a secret.

  • It sends the license itself, in a header, and nothing else: no repository name, code, paths or counts.
  • It runs next to the analysis and waits at most 6 seconds. A failure that may pass is tried again after an hour; if the service cannot be reached, the current license keeps working.
  • HTTPS_PROXY is honoured.
  • TESTDETTA_LICENSE_REFRESH=off turns it off; the license in hand keeps working until it runs out.
  • An annual (offline & enterprise) license carries no renewal address, so {{name}} never calls home for it.

A run without a license makes no call, and public repositories need none. Neither do shadow mode (td test --shadow) and the audit (td audit), which read no license at all. What uses the network in such a job is not {{name}}'s own: the GitHub Action downloads the {{name}} package from nuget.org, checked against the SHA-512 it pins, and lists and restores the coverage maps in your Actions cache; your builds restore packages as usual, shadow mode's rerun on the base commit restores that commit's packages like any build, and the audit's builds and test runs in its copy restore packages the same way.

How the license is checked

A license is a signed string, verified on your machine with a public key built into {{name}}. It names the repositories it covers, matched against the origin remote with any credentials removed first. A license problem never fails a build: every test runs instead, as before {{name}}. More about licenses.

What we keep

For a subscription: the licensee name, the repositories it covers, the number of seats and its period. The payment is handled by {{seller}}, our merchant of record. The license service receives the email address from {{seller}} and passes it to our email provider for the one message that carries the license, without storing it.

For a trial: the email address, until 7 days after the trial ends, for the one reminder; a keyed hash of the address and the organizations you named, for 13 months, to allow one trial per address and organization in 12 months; and the trial's license record (its licensee name, which names your organization, and the repository patterns), kept like any license record.
