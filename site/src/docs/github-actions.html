GitHub Actions

Record a map for every commit on the default branch, and let pull requests run only the tests their changes affect. The action builds {{name}} itself and keeps the maps in the Actions cache.

Workflow

on:
  push:
    branches: [main]
  pull_request:

permissions:
  contents: read
  actions: read # lets pull requests find the newest coverage map in the Actions cache

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7 # pin to a commit SHA
        with:
          fetch-depth: 0 # Sift compares with the merge base
          persist-credentials: false

      - uses: actions/setup-dotnet@v6 # pin to a commit SHA
        with:
          global-json-file: global.json

      # Also the full test run of main. Leave out projects that cannot run here, such as
      # integration tests that need a database; they are then decided by name on pull requests.
      - if: github.event_name == 'push'
        uses: <owner>/sift@<sha>
        with:
          mode: record
          projects: |
            tests/Shop.Tests/Shop.Tests.csproj

      - if: github.event_name == 'pull_request'
        uses: <owner>/sift@<sha>
        with:
          mode: test
          dotnet-test-args: --logger trx
          license: ${{ secrets.SIFT_LICENSE }}

Full history is required. The action stops with an error on a shallow clone. Check out with fetch-depth: 0.

How the maps get to pull requests

  • Record mode saves the maps in the Actions cache under sift-coverage-<commit>. Pull requests can read caches of their base branch.
  • A pull request uses the map of its merge base, or the newest one recorded up to max-map-age first-parent commits before it.
  • Finding that newer-than-exact map lists the repository's caches, which needs actions: read. Without it, only a map at the merge base is found, and the step says so in a notice.
  • Without any map, mode: test still works, deciding by name only.

When tests fail while recording, the map is still saved before the job fails, so pull requests keep a map to work with.

Permissions

PermissionWhy
contents: readCheck out the repository.
actions: readList the Actions caches to find the newest map within max-map-age.

With persist-credentials: false a private repository cannot be fetched again later in the job; fetch-depth: 0 already brings every branch, so the base branch is there.

Job summary

In test mode, {{name}} writes its selection to the job summary: the changed files and the base it compared with, each test project with whether it ran filtered, completely or not at all and why, the test results, and the license state when it matters. Paths, class names and reasons from the repository are written as code, so file names in a pull request cannot inject links or mentions into the page.

Recording only part of the suite

Recording runs the whole suite once with coverage, which on the default branch is also your full test run. Leave out projects that cannot run on the runner, such as integration tests that need a database, with projects. Pull requests then decide those projects by name.

If an earlier step already built the solution with the same configuration, set no-build: true. For a suite that tolerates several test processes at once, parallel spreads each project's test classes over that many processes.
