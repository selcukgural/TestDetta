How it decides

Each step narrows the selection only when it has evidence. Anything it cannot trace falls back to running more.

1

Projects

Changed files map to projects and follow ProjectReferences. Build-wide files such as Directory.Build.props affect everything below them.

2

Symbols

C# syntax trees are compared, so comment and whitespace edits select nothing, and {{name}} knows which members changed.

3

Coverage

A map recorded on your default branch says which test class ran which method, so changed methods select their classes directly.

4

Names

New code, fields and constants are traced through the source by name until they reach test classes or code the map knows.

5

Fallbacks

Configuration files, global usings, reflection-discovered types: when a change cannot be traced, the whole test project runs.

6

Self-checks

A filter that matches no test is treated as a bug in {{name}}, and the project runs again without it.

Two steps in GitHub Actions

Record a coverage map on every push to your default branch. Pull requests restore the newest map and run only the affected tests, with a job summary that says why each class ran or was skipped.
